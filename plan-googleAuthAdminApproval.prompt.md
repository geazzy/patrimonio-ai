## Plan: Autenticação Google + Aprovação Admin (Access + Refresh Tokens)

Implementar autenticação via Google OAuth 2.0 com aprovação de usuários por administrador, usando **Access Token (curta duração) + Refresh Token (longa duração)** armazenado no DB para máxima segurança e revogação real de sessões. Criar tabelas `users` e `refresh_tokens`, seedar admin inicial por ENV, bloquear todas as rotas e permitir acesso apenas a usuários aprovados. No frontend, `AuthGate` controla o fluxo (login, pendente, aprovado).

### Steps
1. **Criar modelo de dados de autenticação**: Em backend/src/services/dbService.ts criar tabela `users` (id, email, name, google_id, is_admin, is_approved, created_at, last_login) e tabela `refresh_tokens` (id, user_id, token_hash SHA-256, expires_at, created_at, last_used_at); adicionar métodos `getUserByEmail()`, `getUserById()`, `createOrUpdateUser()`, `createRefreshToken()`, `validateRefreshToken()`, `revokeRefreshToken()`, `revokeAllUserTokens()`; tipar `User` e `RefreshToken` em backend/src/models/types.ts.
2. **Implementar rotas de autenticação**: Adicionar router `auth` em backend/src/app.ts com `POST /api/auth/google` (valida Google ID token, cria/atualiza user, gera access token JWT 15min + refresh token UUID 30 dias em cookies HttpOnly), `GET /api/auth/me` (retorna user atual ou auto-renova via refresh), `POST /api/auth/refresh` (valida refresh token do DB, rotaciona tokens), `POST /api/auth/logout` (invalida refresh atual), `POST /api/auth/logout-all` (invalida todos refresh do user); usar `google-auth-library`, `jsonwebtoken` e `crypto` (SHA-256).
3. **Criar middlewares de autorização**: Criar backend/src/middleware/auth.ts com `requireAuth()` (valida access token JWT do cookie, se expirado tenta renovar automaticamente via refresh, injeta `req.user`, bloqueia se `!is_approved` com 403) e `requireAdmin()` (verifica `req.user.is_admin`); aplicar `requireAuth` globalmente em backend/src/app.ts para `/patrimonio/api/*` exceto `/patrimonio/api/auth/*` e `/patrimonio/health`.
4. **Implementar gestão de usuários admin**: Criar backend/src/routes/admin.ts com `GET /api/admin/pending-users` (lista não aprovados), `POST /api/admin/approve/:userId` (aprova user), `POST /api/admin/revoke/:userId` (invalida todas sessões), `POST /api/admin/promote/:userId` (torna admin); todas rotas requerem `requireAdmin`; adicionar métodos no dbService: `listPendingUsers()`, `approveUser()`, `revokeUser()`, `promoteToAdmin()`.
5. **Seed do admin e vincular dados a usuários**: Após init do DB em backend/src/server.ts, criar/atualizar admin com `ADMIN_EMAIL` do .env (is_admin=1, is_approved=1); adicionar campo `created_by` (email) em tabela `conference_records`; ajustar rotas para registrar `req.user.email` automaticamente em operações (movement_history.authorized_by, conference_records.created_by).
6. **Implementar AuthGate e integração frontend**: Criar frontend/src/components/AuthGate.tsx com Google Sign-In button (biblioteca `@react-oauth/google`), gerencia 3 estados (não-autenticado, pendente aprovação, aprovado), chama `/api/auth/google` com credential; envolver App em AuthGate; ajustar frontend/src/services/apiService.ts para `credentials: 'include'`, adicionar interceptor de 401 que chama `/api/auth/refresh` automaticamente, métodos `loginWithGoogle()`, `getMe()`, `logout()`, `logoutAll()`; criar componente admin frontend/src/components/AdminPanel.tsx para gerenciar usuários pendentes.

### Further Considerations
1. **Cleanup de tokens expirados**: Implementar job cron diário para deletar `refresh_tokens` com `expires_at < NOW()` ou usar lazy deletion no `/auth/refresh`?
2. **Detecção de roubo de token**: Rotação estrita (refresh usado 2x invalida todas sessões) ou permitir reuso em janela de 5s (clock skew)?
3. **Whitelist de domínios**: Auto-aprovar emails `@empresa.com` ou manter aprovação manual total?
4. **Auditoria**: Criar tabela `audit_log` para logins/logouts/aprovações com timestamp, IP, user-agent ou apenas `last_login` em `users`?
